# Ревью пирамиды метрик

Полный аудит готовой пирамиды. Работай строго по шагам, без пропусков.

## Шаг 1. Загрузить пирамиду

- Если указан путь к `.md` (например `PROJECTS/<X>/AGENT_RESULT/Пирамида метрик.md`) — прочитай файл.
- Если указано имя проекта — возьми артефакты из `PROJECTS/<X>/AGENT_RESULT/` и карточку `PROJECTS/<X>/PROJECT.md`.
- Если пирамида приведена прямо в сообщении — работай с ней.
- Чего не хватает (JTBD, цепочка связи уровней, красные флаги, пороги) — спроси пользователя через `question`.

## Шаг 2. Прогнать чек-лист

Открой [`../metrics-pyramid/CHECKS.md`](../metrics-pyramid/CHECKS.md) и пройди **все 21 пункт** для загруженной пирамиды.

## Шаг 3. Проверить правило иерархии

Для каждой метрики нижних уровней (L2–L5): не роняет ли она верхний уровень (L1)?

Для каждой инициативы/гипотезы из артефактов: улучшает ли нижний уровень и не роняет ли верхний?

Нарушение правила иерархии = блокер, независимо от счёта чек-листа.

## Шаг 4. Выдать отчёт

Таблица по всем пунктам:

| # | Пункт чек-листа | Y/N | Что чинить |
|---|-----------------|-----|------------|

- **Y** — выполнено; **N** — не выполнено (обязательно «что чинить»); «—» — неприменимо (объяснить почему).
- После таблицы: список блокеров (нарушение правила иерархии, двойной NSM, ненормированные метрики) и топ-3 доработки по приоритету.

## Шаг 5. Обновить карточку проекта

Если пользователь согласовал правки — обнови `PROJECTS/<X>/PROJECT.md` (ключевые решения).
