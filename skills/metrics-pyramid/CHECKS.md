# Валидация пирамиды метрик

Прогоните этот чек-лист перед выдачей пирамиды пользователю. Любой невыполненный пункт — повод доработать пирамиду.

## Уровень 1 (Бизнес)
- [ ] Есть конкретное число (текущее → целевое за период)
- [ ] Нет vanity-метрики (регистрации без retention, скачивания без активации)
- [ ] Если без монетизации — явно указано «pre-revenue»

## Уровень 2 (Маржинальность)
- [ ] LTV/CAC ≥ 3 (или явно указано почему нет)
- [ ] Указан период когорты для LTV
- [ ] Не путать с уровнем 1 (LTV — не валовая метрика)

## Уровень 3 (Лояльность)
- [ ] Retention взят по когортам, не «общий процент»
- [ ] Sticky указан только если ежедневное использование осмысленно
- [ ] C2 ≠ Retention (оплата vs использование)
- [ ] Конверсии сформулированы полно: источник → целевое действие, окно, когорта

## Уровень 4 (NSM)
- [ ] Одна метрика, не две
- [ ] Клиентоцентрична (выигрывает клиент, не бизнес)
- [ ] Сформулирована через JTBD
- [ ] Коррелирует с Retention

## Уровень 5 (Качество)
- [ ] Разделены «помогает» и «мешает»
- [ ] Метрики нормированы (на сессию / пользователя / единицу услуги)
- [ ] Баги даны в 3-х разрезах (на сессию, на пользователя, доля юзеров за месяц)
- [ ] Время → доля от сессии, а не абсолют
- [ ] Каждая метрика имеет интерпретацию направления (не «режим работы X»)

## Сквозные
- [ ] Связь уровней прописана: NSM↑ → Retention↑ → LTV↑ → Revenue↑
- [ ] Указаны красные флаги с порогами (например, успешные команды <95%, Sticky <15%)
- [ ] Использована медиана за сутки, не среднее за период
- [ ] Применено правило иерархии (не роняем верхний уровень ради нижнего)
