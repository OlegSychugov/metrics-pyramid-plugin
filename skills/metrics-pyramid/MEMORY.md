# Работа с памятью (Knowledge Graph)

Агент учится на ошибках и обратной связи, сохраняя уроки в Knowledge Graph Memory (MCP `memory`). Память — единственный источник долгосрочного опыта; артефакты проектов в графе не хранятся.

## При старте сессии

**Обязательно:** вызовите `memory_read_graph` для полного чтения графа.

`memory_read_graph` надёжнее `memory_search_nodes` — последний может не найти запись при неточном запросе. Прочитайте все сущности и учитывайте уроки, предпочтения и паттерны из прошлых сессий.

## Типы сущностей

В графе хранятся только сущности учебного опыта:

| Тип | Назначение |
|-----|-----------|
| `MetricsLesson` | Конкретный урок или исправление из проекта |
| `MetricsPreference` | Предпочтения пользователя по формату/стилю/тональности |
| `MetricsPattern` | Удачный паттерн метрик для конкретного типа продукта |
| `Project` | Карточка реального проекта (тип, JTBD, NSM, путь к артефактам) |
| `Reviewer` | Эксперт, давший фидбек |
| `MetricLevel` | Якорь-уровень пирамиды (Бизнес/Маржинальность/Лояльность/Ценность/Качество) |

**Чего в графе быть НЕ должно:**
- Структура файловой системы (она в `AGENTS.md`).
- Клоны пирамид проектов (они в `PROJECTS/{X}/AGENT_RESULT/*.xlsx`).
- Служебная инфа про конфигурацию инструментов.

## Шаблоны сущностей

### MetricsLesson

```json
{
  "entities": [
    {
      "name": "Урок: нормировка метрик качества",
      "entityType": "MetricsLesson",
      "observations": [
        "ГГГГ-ММ-ДД: краткое описание проблемы",
        "Решение: что делать вместо",
        "Контекст: тип продукта, стадия, источник фидбека",
        "Применимость: уровни пирамиды, типы продуктов"
      ]
    }
  ]
}
```

### MetricsPreference

```json
{
  "entities": [
    {
      "name": "Предпочтение: формат вывода",
      "entityType": "MetricsPreference",
      "observations": [
        "ГГГГ-ММ-ДД: пользователь предпочитает таблицы вместо ASCII-арта",
        "Контекст: проект X"
      ]
    }
  ]
}
```

### MetricsPattern

```json
{
  "entities": [
    {
      "name": "Паттерн: B2B SaaS метрики",
      "entityType": "MetricsPattern",
      "observations": [
        "ГГГГ-ММ-ДД: типичные метрики MRR, NRR, CAC payback",
        "NSM обычно: time-to-first-value (activation)",

      ]
    }
  ]

```

### Связи

```json
{
  "relations": [
    {"from": "Урок: X", "to": "Проект Y", "relationType": "получен из"},
    {"from": "Урок: X", "to": "Имя Фамилия — ревьюер", "relationType": "автор фидбека"},
    {"from": "Урок: X", "to": "Уровень: Качество", "relationType": "применяется на"}
  ]
}
```

## Жизненный цикл урока

1. **Триггер.** Пользователь:
   - Исправляет ваш ответ («NSM должен быть другим»).
   - Указывает на ошибку или упущение.
   - Просит изменить подход/стиль.
   - Хвалит конкретный результат и формулирует почему.

2. **Поиск дубля.** Перед созданием — `memory_search_nodes` по ключевым словам. Если похожий урок есть — `memory_add_observations`, не плодите дубли.

3. **Сохранение.** `memory_create_entities` сразу после получения фидбека, не откладывая.

4. **Связи.** `memory_create_relations`:
   - Урок → Проект (`получен из`)
   - Урок → Ревьюер (`автор фидбека`), если применимо
   - Урок → Уровень пирамиды (`применяется на`), один или несколько

5. **Использование.** На старте новой сессии и при выборе метрик — сверяйтесь с уроками.

## Правила формулировки урока

1. Каждое наблюдение начинайте с даты `ГГГГ-ММ-ДД`.
2. Формулируйте как конкретное действие: «делать X вместо Y», а не «X — это плохо».
3. Обязательные поля наблюдений: проблема, решение, контекст, применимость.
4. Контекст указывает: тип продукта, стадия, источник фидбека.
5. Применимость — на какие уровни пирамиды и типы продуктов переносится.

## Приоритет памяти

Уроки из графа имеют приоритет над общими шаблонами из `SKILL.md`, `REFERENCE.md`, `EXAMPLES.md`. Если пользователь однажды исправил подход — всегда используйте исправленный вариант.

## Анти-паттерны

- ❌ Не хранить в графе пирамиды проектов целиком (они в Excel).
- ❌ Не хранить структуру ФС (она в `AGENTS.md`).
- ❌ Не плодить одинаковые уроки — обновляйте через `memory_add_observations`.
- ❌ Не сохранять урок без связей с уровнем и проектом.
- ❌ Не использовать `memory_search_nodes` вместо `memory_read_graph` на старте сессии.
