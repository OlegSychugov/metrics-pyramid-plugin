# Как прогонять eval-кейсы

Регрессионный воспроизводимый тест агента после изменения `SKILL.md` / `CHECKS.md` / `heuristics.md`.

## Когда прогонять

- После любой правки в `skills/metrics-pyramid/SKILL.md`.
- После реструктуризации `METHODOLOGY/` или `CHECKS.md`.

## Процедура (ручная)

Для **2–3 кейсов из `briefs.md`** (выбирайте те, что покрывают изменения):

1. **Открой новый чат** (свежий контекст).
2. **Дай агенту бриф.** Например: «Действуй по `AGENTS.md`. Используй кейс №3 из `EVALS/briefs.md`, секция "Контекст" и "JTBD". Построй пирамиду без подсказок про эталон.»
3. **Не подсказывай.** Не открывай агенту секцию «Эталон». Пусть пройдёт workflow.
4. **Сравни результат с эталоном.** Зафиксируй:
   - NSM попал в допустимый список? (Y / N / частично)
   - Все обязательные метрики по уровням покрыты? (доля %)
   - Применены ли обязательные эвристики? (счёт N из M)
   - Прошёл ли итоговый CHECKS.md? (N / 21 пунктов выполнено)
5. **Запиши результат** в `EVALS/runs/<дата>.md` (создай папку при первом прогоне):

```markdown
# Прогон от ГГГГ-ММ-ДД

## Кейс №3 (фитнес)
- NSM: ✅ / ⚠️ / ❌
- Метрики уровней: 12/15
- Эвристики: 3/4 (пропущено: №3 — не использовал медиану)
- CHECKS: 18/21

## Что починить
- Добавить в SKILL.md шаг 6 явное упоминание медианы.
```

## Что считаем регрессией

- NSM **не** попал в допустимые варианты.
- Пропущена ≥1 обязательная эвристика из брифа.
- CHECKS.md прошёл <17/21 пунктов.

## Что НЕ делаем

- ❌ Не автоматизируем прогон (LLM-нестабильность, не имеет смысла без жёстких эвалов).
- ❌ Не добавляем «эталонную пирамиду» — тестируем направление, а не точное совпадение.
- ❌ Не правим бриф под текущее поведение агента — правим агента.
